# TASK-M1.2: `list <Aggregate>` sem cláusulas em EmitQuery

## 1. Contexto & Objetivo
> **Instrução para o Claude Code:** Leia [design.md](../design.md) §4.2 e §5.1 antes de iniciar. Modifique **apenas** os arquivos de `target_files`.

`emitReturn` ([decl_query.go](../../../../../codegen/decl_query.go)) não reconhece `list <Aggregate>`:
`tryEmitListVO` devolve `handled=false` porque o `Target` resolve a um Aggregate,
não a um `*types.VOType`; `tryEmitHoistedQueryReturn` exige `Op == "load"`; e o
fallback `qc.l.Expr(...)` rejeita `QueryExpr` em posição pura. Reproduzido:
`dsc gen docs/examples/pizzeria` sai 2 em `Query GetBoardTickets`.

Esta task entrega a **forma base** — `list <Aggregate>` sem cláusula nenhuma,
com ou sem `as <View>`. As cláusulas (`where`/`orderBy`/`skip`/`take`) ficam para
M1.3, que reusa a máquina do Marco I.

**Não confundir com `list <VO>`:** aquela lista os itens de um campo
`AppendList<VO>` de **uma** instância correlacionada; esta enumera **todas** as
instâncias do Aggregate. As duas convivem — ver a tabela de formas em
[design.md](../design.md) §4.2.

## 2. Passos de Implementação
- [ ] **Step 1:** Em [decl_query.go](../../../../../codegen/decl_query.go), criar `tryEmitListAggregate(qe)
  (handled bool, err error)`, irmão de `tryEmitListVO`: reconhece `Target` como
  `*ast.Ident` que resolve a um Aggregate (via `qc.env.TypeOfName` / o
  `symbols.KindAggregate` que `qc.shapeOf` já consulta). `handled=false` sem erro
  quando não é essa forma.
- [ ] **Step 2:** Encadeá-la em `emitReturn`, no ramo `qe.Op == "list"`,
  **depois** de `tryEmitListVO` (que continua tendo precedência para a forma VO)
  e antes do fallback genérico.
- [ ] **Step 3:** Emitir a materialização: `ListStreams(ctx, "<Agg>")` sobre a
  store, loop chamando o `Load<Agg>(runtime.NewEventLoader(ctx, store), id)` já
  gerado, acumulando `.state` num `[]<aggStateStruct>`
  (`aggregateStateStructName`, [decl_aggregate.go](../../../../../codegen/decl_aggregate.go)). Propagar erro de cada
  `Load` com `ZeroValues` correto para o tipo de retorno da Query.
- [ ] **Step 4:** Erro claro quando a store não implementa `StreamLister`
  (REQ-55.5): a type assertion falha → mensagem **nomeando o Aggregate e a
  Query**. Nunca Go que não compila, nunca lista silenciosamente vazia.
- [ ] **Step 5:** `as <View>`: reusar `projectFieldAssignments` (state → View), o
  **mesmo** par `aggShape.Fields`/`viewShape.Fields` que `emitLoadAsView` já usa.
  Sem `as`, validar que o tipo de retorno declarado bate com a forma
  (`listReturnElement`), no mesmo espírito do erro que `tryEmitListVO` já produz.
- [ ] **Step 6:** Em `lower/env.go`, fazer `ItemTypeOf` resolver a forma
  `list <Aggregate>` para o tipo do state do Aggregate — é o que o binding
  (`t` em `list KitchenTicket t`) denota.

## 3. Testes & Validação

### Casos de Teste Unitários / Golden Tests
- [ ] **TEST-1 (positivo):** fixture sintética com `Query All() ->
  List<XView> { return list X as XView }` → gera, e `gentest.SmokeCompile`
  **builda** o projeto (golden sozinho não prova que compila, NFR-17).
- [ ] **TEST-2 (negativo):** a mesma Query contra uma store sem `StreamLister`
  produz **erro claro** nomeando o Aggregate e a Query — não Go quebrado. E uma
  Query cujo tipo de retorno não bate com a forma (`-> XView` em vez de
  `List<XView>`) falha com mensagem apontando o tipo declarado.
- [ ] **TEST-3 (byte-identidade, NFR-31):** `list <VO>` sem e com cláusulas,
  `load … as V` e a forma de join geram Go **byte-idêntico** ao de hoje — a
  precedência de `tryEmitListVO` não foi alterada.
- [ ] **TEST-4 (determinismo, NFR-13):** gerar a mesma Query duas vezes produz
  bytes idênticos.
