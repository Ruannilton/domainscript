# TASK-M4.1: Shrinking determinístico do contra-exemplo de `property` (§22.5)

## 1. Contexto & Objetivo
> **Instrução para o Claude Code:** Leia `design.md` §4.5 (parágrafo "Shrinking") antes de iniciar. Modifique **apenas** os arquivos de `target_files`.

Uma `property` que falha hoje reporta a sequência **completa** de passos
(`dsPropStep`). O cabeçalho de `gentest_property.go` já documenta a ausência de
shrinking e aponta o caminho: "re-executar prefixos candidatos contra o MESMO
seed determinístico".

A boa notícia, verificada: **a base determinística já existe**. Cada property roda
com `rand.New(rand.NewSource(propertySeed(t.Name, pr.Name)))` — semente derivada
do par de nomes, **nunca** `time.Now`. O shrinking herda esse determinismo se for
construído sobre a mesma semente.

## 2. Passos de Implementação
- [ ] **Step 1:** No caminho de **falha** (e só nele — REQ-58.3), encolher a
  sequência acumulada: remoção/bissecção de passos, re-executando cada candidata
  a partir do **mesmo state seedado**, até o mínimo que ainda viola a invariante.
- [ ] **Step 2:** Garantir que cada re-execução parte de um state limpo e
  idêntico ao original — um shrink que reusa state mutado dá contra-exemplo
  errado. Reusar o mesmo mecanismo de seed de state que o corpo já emite.
- [ ] **Step 3:** Garantir terminação: limite explícito de iterações de shrink e
  progresso monotônico (cada candidata aceita é estritamente menor), no espírito
  de `propGenMaxAttempts` que o arquivo já usa como defesa.
- [ ] **Step 4:** Reportar a sequência **mínima** no `t.Fatalf`, mantendo o
  formato legível de hoje (Handle + args concretos, suficiente para replay
  manual) e indicando que houve shrinking — quantos passos foram eliminados.
- [ ] **Step 5:** Confirmar que a semente e a ordem de geração não mudam: a
  sequência **original** gerada deve continuar sendo a mesma de hoje, para uma
  property que passa não mudar nada (REQ-58.4).

## 3. Testes & Validação

### Casos de Teste Unitários
- [ ] **TEST-1 (positivo/falha):** property com invariante violada por **um**
  passo no meio de uma sequência longa → o contra-exemplo reportado tem
  exatamente esse passo (mínimo), e rodar o teste gerado **duas vezes** produz o
  **mesmo** contra-exemplo (determinismo, REQ-58.2).
- [ ] **TEST-2 (negativo/silêncio):** property que **passa** → nenhum shrinking
  executado e nenhuma mudança observável de comportamento nem de bytes gerados
  no caminho verde.
- [ ] **TEST-3 (terminação):** uma property cuja invariante falha em **todos** os
  passos ainda termina, dentro do limite de iterações, sem loop.
- [ ] **TEST-4 (byte-identidade, NFR-31):** as properties das fixtures existentes
  geram Go byte-idêntico no que não é o caminho de falha; `wallet` e `shop` sem
  regressão.
