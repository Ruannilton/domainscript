# TASK-M3.2: Implementar `result = call Adapter(...)` (§18.2)

## 1. Contexto & Objetivo
> **Instrução para o Claude Code:** A decisão de M3.1 em `design.md` §4.5 é **normativa**. Se M3.1 escolheu delimitar, esta task **não deve ser executada**. Modifique **apenas** os arquivos de `target_files`.

`result = call PaymentRequest(...)` é a forma que está no **exemplo de Saga do
próprio spec** (§18.2) e que nunca foi implementada: passa o front-end e falha a
geração com

> `QueryExpr.Op "call" (chamada síncrona via Adapter/Notification) não é
> suportado — fora do escopo de G1a`

(`codegen/lower/builtins.go`). Fechar isto **tem valor próprio**, independente de
teste — é uma forma documentada do spec que o back-end não entrega.

Só depois desta task é que M3.3 (`mock … returns X`) tem canal de valor por onde
o mock influencie o fluxo.

## 2. Passos de Implementação
- [ ] **Step 1:** Em `decl_io.go`, alterar a emissão de `Call<Nome>` para
  devolver `(<Tipo>, error)` conforme o contrato de M3.1, no lugar de só `error`.
  Manter a forma-statement (chamar `Call<Nome>` e descartar o valor) gerando
  **exatamente** como hoje.
- [ ] **Step 2:** Em `lower/builtins.go`, remover o erro explícito de
  `QueryExprPure` para `Op == "call"` e implementar o lowering: hoisting do
  argumento, chamada, e o valor ligado ao alvo da atribuição — no mesmo padrão
  "hoist then use the temp" que `hoistStore`/`hoistLoad` já seguem.
- [ ] **Step 3:** Registrar o tipo do temporário no `TypeEnv` (`bindTmp`) para
  que o uso subsequente de `result` tipeche corretamente no lowering seguinte.
- [ ] **Step 4:** Propagar o erro do adapter pelo `ctx.ExitOnError` do
  `StmtContext` ao redor, como as outras formas falíveis fazem — não engolir.
- [ ] **Step 5:** Atualizar `builtins_test.go`, que hoje afirma que `"call"` é um
  dos ops rejeitados (a lista `{"store", "call", "delete"}`) — `call` sai dela.

## 3. Testes & Validação

### Casos de Teste Unitários / Golden Tests
- [ ] **TEST-1 (positivo):** um passo de Saga com `result = call X(...)` seguido
  do uso de `result` gera e `gentest.SmokeCompile` **builda**.
- [ ] **TEST-2 (positivo, erro propagado):** quando o adapter falha, o passo
  devolve o erro (teste comportamental sobre o projeto gerado).
- [ ] **TEST-3 (negativo):** `call` sobre um alvo que não é Adapter deste módulo,
  ou com aridade errada, produz erro de geração claro.
- [ ] **TEST-4 (byte-identidade, NFR-31):** um passo que chama o Adapter como
  **statement** (a forma de hoje, sem capturar valor) gera Go **byte-idêntico**;
  `wallet` e `shop` sem regressão. `store` e `delete` seguem rejeitados como
  antes.
